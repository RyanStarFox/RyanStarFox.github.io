¶3 Single-cycle Processor

4 stages:

  • IF (instruction fetch)
    • PC+=4 in each cycle
    • for branch
      • A PC Ext (signed) to add immediate to PC
      • A zero flag to determine whether to add immediate to PC
    • for I-type: replace lower 28 bits of PC with the lower 26 bits of the fetched instruction shifted left by 2 bits
  • Decode
    • for R-type
      • Generate a RegWr signal for Registers
      • Generate a ALUctr signal for Registers
    • for I-type
      • calculation, like ori
        • Expand immediate from 16 bits to 32 bits (unsigned/zero extension)
        • need a multiplexer, because in R-type write to Rd but in I-type write to Rt
      • memory access, like lw & sw
        • Expand immediate from 16 bits to 32 bits (signed extension)
    • for J-type
      • shift lower 26 bits of the fetched instruction by 2 bits (*4)
  • Execute
  • Memory
  • (Reister write) only lw

¶5.3 Pipeline hazards

  • Structure hazard：不同指令在统一时间周期内需要访问同一个硬件资源

    解决方法：

    • 给多个端口访问内存
    • Instruction Memory和Data Memory分离

  • Data hazard：前一个指令还没完成对于Data的修改，后一个指令就已经读取了数据，ID阶段就需要检查

    解决方法：

    • Code Scheduling：不改变执行结果的情况下，让两条Data hazards的指令隔得远一点
    • Forwarding/Bypassing：通过硬件，不待数据存回内存，就直接给到下一条指令，但是即便如此，lw后一个需要读寄存器的指令依旧会有Data hazard
    • Stalling：给一条空指令（Bubble）

  • Control hazard：Branch影响了Instruction流

    解决方法：

    • 把branch提前到ID之后，减少Bubble从2个变为1个
    • 延迟分支和延迟槽：再增加一个无论都会执行的分支，包含两个延迟槽，填充原来两个bubble的位置
    • 分支预测：预测（猜）下一个进入哪一个分支
      • 静态：总是跳转/不跳转
      • 动态：
        • 1位预测器：根据上一次的结果
        • 2位预测器：00，01，10，11，跳转加1，不跳转减1，只有到00和11的时候，才会改变跳不跳转的状态
        • 全局/局部历史预测
      • prediction correct就继续运行，错误则原来的预测直接flush掉，称为bubble，立即执行正确的

¶7 Memory Hierarchy Design

¶7.1 Cache Organization

Principle of Locality: Programs tend to reuse data and instructions near those they have used recently, or those were recently referenced themselves.

  • Temporal locality: Recently referenced items are likely to be referenced in the near future.
  • Spatial locality: Items with nearby addresses tend to be referenced close together in time.

一个block的结构：

Block address Block
offset
Tag Index
对于一个Four-Way Set Associative Cache，先通过Index定位到一个包含4个Block的组，再通过tag来找到（或者找不到）正确的block，然后再通过Block Offset找到正确的byte

Bits per row = Data Bits (Block Size in bits) +Tag Bits+Valid Bit

Cache大小的计算：如果一个32位block是22位tag，8位index，2位block offset，又是一个4-way cache，则：

  • set的数量：2^8
  • 每个set中block的数量：4=2^2
  • 每个block中Byte的数量：2^2

所以总大小：2^8^$\times$2^2^$\times$2^2^B=2^12^B=4KB

如果出现Miss的情况，需要替换掉一个block，LRU/FIFO/Random

Write strategy：

  • write through：每次都写进cache和memory
  • write back：每次写进cache，只有在替换block的时候写进memory

Handling

  • Cache Hits
    • Read hits: Just read it !
    • Write hits
      • require the cache and memory to be consistent
        • write through
        • slow
        • can use a write buffer or stall when write buffer is full
      • allow cache and memory to be inconsistent
        • write back
        • need dirty bit to tell whether or not required to write back to memory
        • can use a write buffer when writing back
  • Cache Misses
    • Read Misses: block size增加，miss penalty也增加；miss一个word要从memory获得一整个block
      • 一收到block中的word，不等block完全上传完就执行
      • 需要的word先传，再传block剩下的部分
      • 非阻塞式cache：处理器在cache在处理先前miss的时候还可以继续获取cache中的内容
    • Write Misses: 先把block加载到cache，再写

CPU Time = (CPU Execution Clock Cycles + Memory Stall Clock Cycles) $\times$ Cycle Time

因此cache行为对CPU time影响很大

¶7.3 Six Basic Cache Optimizations

Average Memory Access Time = Hit Time + Miss Rate $\times$ Miss Penalty

  1. Reducing the miss rate

    Larger block size, larger cache size, higher associativity

  2. Reducing the miss penalty

    Multilevel caches, giving reads priority over writes

  3. Reducing the time to hit in the cache

    Avoiding address translation when indexing the cache

  • Compulsory

    The very first access to a block cannot be in the cache

  • Capacity

    If the cache cannot contain all the blocks needed during execution of a program, capacity misses occur

  • Conflict

    In case of set associative and direct mapped, conflict misses occur. Different blocks mapped onto the same place

¶6 指令级并行

¶6.1 概念与挑战

目标是最小化CPI（每条指令的平均时钟周期数）。指令间存在三种依赖关系：

  • 数据依赖：一条指令的结果被另一条指令使用
    • 真依赖：前序指令的结果供后续指令读取
    • 反依赖：后续指令会写入前序指令读取的寄存器
    • 输出依赖：多条指令写入同一个寄存器
  • 名称依赖：两条指令使用相同的寄存器或内存位置，但无实际数据关联，可通过寄存器重命名消除
  • 控制依赖：指令的执行结果取决于控制流（如分支指令）的判断结果

数据冒险类型：

  • 写后读（RAW）：后续指令读取前序指令写入的数据
  • 写后写（WAW）：后续指令覆盖前序指令写入的数据
  • 读后写（WAR）：后续指令覆盖前序指令读取的数据

¶6.2 基础编译器技术

  1. 流水线停顿：插入空操作指令填补流水线空隙
  2. 流水线调度：调整指令顺序避免冒险
  3. 循环展开：减少跳转开销，例如将一次循环的内容拆分为4次执行，需提前计算余数

¶6.3 利用高级分支预测降低分支代价

控制推测机制：若推测错误，需启动恢复机制，丢弃错误路径上的指令。
分支预测分为动态预测和静态预测，相关内容可参考5.3节的控制冒险部分。

¶6.4 通过动态调度克服数据冒险

指令译码阶段拆分为两部分：

  • 检测是否存在结构冒险
  • 等待数据冒险解除后再继续执行

为进一步提升效率，可采用按序发射、乱序执行策略：先按顺序将指令送入发射队列，再根据数据就绪情况乱序执行，从而减少数据冒险。实现步骤为：

  1. 列出所有WAR和WAW冒险
  2. 动态调度
    • 优点：编译器无需了解微架构细节，可处理未知的依赖关系
    • 缺点：硬件更复杂，异常处理逻辑也更繁琐

¶7 存储层次设计

¶7.1 缓存组织

flowchart TD
Regfile---ITLB
Regfile---DTLB
ITLB---InstrCache
DTLB---DataCache
InstrCache---SRAM["二级缓存（SRAM）"]
DataCache---SRAM
SRAM---DRAM["主存（DRAM）"]
DRAM---Disk["辅助存储（磁盘）"]

局部性原理：程序倾向于复用近期使用过的数据或指令，或访问地址相邻的数据。

  • 时间局部性：近期被访问的项未来很可能再次被访问
  • 空间局部性：地址相邻的项往往会在相近时间被访问

块的结构：

块地址 块
偏移
标签 索引
以四路组相联缓存为例：先通过索引定位到包含4个块的组，再通过标签匹配正确的块，最后通过块偏移定位到具体的字节。

每行包含的位数 = 数据位（块大小对应的位数）+ 标签位 + 有效位。
若32位块的大小对应22位标签、8位索引、2位块偏移，且为四路缓存，则：

  • 组的数量：2^8
  • 每组中的块数量：4=2^2
  • 每个块包含的字节数：2^2
    总大小为：2^8 × 2^2 × 2^2 B = 2^12 B = 4KB。

当发生缓存缺失时，需替换掉一个块，常用替换策略有LRU、FIFO、随机替换。

写策略：

  • 写穿透：每次写操作同时更新缓存和主存
  • 写回：仅更新缓存，只有在该块被替换时才写回主存

缓存命中时的处理：

  • 读命中：直接读取即可
  • 写命中：
    • 要求缓存和主存数据一致：采用写穿透方式，速度较慢，可使用写缓冲区，或当写缓冲区满时暂停执行
    • 允许缓存和主存数据不一致：采用写回方式，需通过脏位标识该块是否需要写回主存，写回时可借助写缓冲区

缓存缺失时的处理：

  • 读缺失：块大小越大，缺失代价越高；读取一个字时需从主存载入整个块。可采用以下优化：
    • 收到块中的字后，无需等待整个块加载完成就开始执行
    • 优先传输所需的字，再传输块的剩余部分
    • 非阻塞式缓存：处理器可在处理先前缺失请求的同时，继续从缓存获取其他数据
  • 写缺失：先将块载入缓存，再执行写入操作

CPU时间计算公式：
CPU时间 = (CPU执行时钟周期 + 内存停顿时钟周期) × 时钟周期时间
可见缓存行为对CPU时间影响极大。

¶7.2 虚拟内存

虚拟页号 + 页偏移 → 物理页号 + 页偏移。由于需要通过页表在物理页中查找与请求的虚拟页号匹配的页，这一过程耗时较长，因此引入TLB解决该问题（TLB仅用于查找数据地址，不负责读取数据，数据读取相关内容见7.1节）。

¶7.3 六种基础缓存优化

平均内存访问时间 = 命中时间 + 缺失率 × 缺失代价

  1. 降低缺失率：增大块大小、扩大缓存容量、提高相联度
  2. 降低缺失代价：采用多级缓存，优先处理读请求而非写请求
  3. 缩短缓存命中时间：索引缓存时避免地址转换过程

缺失的三类原因：

  • 强制性缺失：首次访问某个块时，该块不可能已在缓存中
  • 容量缺失：程序执行过程中所需的块无法全部存入缓存
  • 冲突缺失：在组相联或直接映射缓存中，不同块被映射到同一位置导致

  • 提高相联度：可提供更多数据存储位置，从而减少冲突缺失
  • 优先处理读缺失请求：通常写操作可暂存在写缓冲区中，因此可等待
  • 避免地址转换：让缓存直接使用虚拟地址访问，省去转换步骤，但存在以下问题：
    • 不同运行中的进程的虚拟地址会相互干扰
    • 进程切换时需要清空缓存
    • 不同虚拟地址可能映射到同一物理地址（别名/同义现象），会导致数据写入不同步

因此采用折中方案：VIPT（虚拟索引、物理标签）。要求：一页只能映射到一个缓存组。
例如四路缓存：

  1. 利用虚拟地址的低位部分（页内偏移），该部分包含缓存组索引和块偏移，可直接查询对应组，提取其中4个块的标签
  2. 通过虚拟页号得到物理页号，从而获得物理地址的标签
  3. 对比两个标签判断是否命中，命中则返回结果，未命中则触发缓存缺失，进一步访问主存

限制条件：缓存大小 = 页面大小 × 相联度

虚拟页号 页内偏移
标签（物理页号） 索引 块偏移

缓存大小 = 组数 × 相联度（每组中的块数） × 块大小 = 2^索引位数 × N × 2^字节偏移位数

最小页面大小 = 缓存大小 ÷ 相联度 = 组数 × 块大小 = 2^索引位数 × 2^字节偏移位数

¶7.4 十种高级缓存性能优化

  1. 小巧简单的一级缓存
  2. 路径预测
  3. 缓存流水线化
  4. 非阻塞缓存：允许在前序缺失请求完成前就处理命中请求
  5. 多体缓存：支持同时访问
  6. 关键字优先、提前重启
  • 关键字优先：优先请求关键字数据供CPU使用
  • 提前重启：按顺序请求数据，拿到关键字后立即提供给CPU，无需等待全部加载完成
  1. 合并写缓冲区：若要写入的数据已在写缓冲区中，直接更新缓冲区内容
  2. 编译器优化：例如矩阵读取顺序从左右上下调整为上下左右
  3. 硬件预取：利用原本闲置的内存带宽
  4. 编译器预取：在需要数据前插入预取指令（寄存器/缓存）

¶7.5 存储技术与优化

性能核心指标：延迟与带宽。

  • SRAM：主要用于缓存，结构复杂且成本高
  • DRAM：主要用于主存，结构简单且比SRAM便宜
  • 闪存：属于EEPROM的一种
  • 新趋势：NVM（非易失性存储器）

¶8 数据级并行

¶8.1 简介

相关内容可参考1.2节最后的Flynn分类法，包括SISD、MISD、SIMD、MIMD。
SIMD的优势：

  • 可充分利用数据级并行
  • 能效更高
  • 对程序员更友好

¶8.2 向量架构

基本思路：

  • 将一组数据元素读入“向量寄存器”
  • 对这些寄存器执行运算
  • 将结果分散写回内存

VMIPS架构：

  • 向量寄存器：包含64个元素，每个元素为64位；有16个读端口和8个写端口（每次读写一个元素）
  • 向量功能单元：全流水线设计，可检测数据和控制冒险
  • 向量加载存储单元：全流水线设计，初始延迟后每个时钟周期可传输一个字
  • 标量寄存器：32个通用寄存器，32个浮点寄存器

向量算术运算采用更深度的流水线：由于向量中的元素相互独立，不会产生冒险，因此可简化深度流水线的控制逻辑。
向量操作序列的执行时间由三个因素决定：

  • 操作数向量的长度
  • 结构冒险
  • 数据依赖

通过向量长度寄存器（VLR）控制任何向量操作的长度，包括向量加载和存储。
向量掩码寄存器：用于选择参与运算的位。
大多数向量处理器采用内存库设计，以支持多个独立访问操作。

¶8.3 SIMD指令集扩展

向量架构成本高且制造难度大，因此采用折中方案：通过SIMD指令在普通架构的机器上实现近似向量机的效果。许多指令会附加“.4D”这类后缀，表示一次可处理4个双精度数据。

CUDA（统一计算设备架构）具备高度并行特性。

           网格

  │    块0      块1      ...    │ ← 一个网格中包含多个块
  │  ┌──────────┐  ┌──────────┐ │
  │  │ 线程x    │  │ 线程x    │ │ ← 每个块中包含多个线程
  │  │ 线程y    │  │ 线程y    │ │

  └─────────────────────────────┘

一个函数对应一个内核，即一个网格，网格下划分多个块，块中包含多个线程。块之间不共享数据，线程之间可共享数据。块是调度单位，线程是运算单位，一般一个块中最多包含1024个线程。

例如：若一个函数需要对8192位数据进行取反操作，该函数即为一个内核，对应一个网格，可划分为8个块，每个流式多处理器（SM）负责运行一个块，每个SM内部可同时运行1024个线程。
